# v2 Build Steps — Agentic Orchestrator Proof Artifact

> **Status:** Planning only. Do not build until Scott explicitly says to start implementation.

**Goal:** Build a clear, gamified Agentic Engineering proof artifact where visitors orchestrate multiple simulated businesses in parallel, assign agents/interventions, solve tiny optional puzzles, and understand why Scott is worth hiring for AI systems architecture, local-first workflows, and modernization.

**Architecture:** Use a hybrid product/UI architecture: semantic HTML/CSS for clarity, proof, accessibility, SEO, and conversion; selective Three.js only for moments where 3D clarifies orchestration, transformation, or surprise. Begin as a preview route in the existing Next.js repo, then promote only after validation.

**Tech Stack:** Next.js, React, TypeScript, direct Three.js for selective scenes, existing styling/Tailwind conventions, deterministic local state first. No OpenAI Agents SDK in the first implementation; simulate agents until privacy/cost/safety constraints are resolved.

---

## Guiding build principles

1. **Hiring clarity first.** The site must make someone understand why they should hire Scott.
2. **Three.js only where needed.** Use 3D for orchestration maps, transitions, puzzles, and surprise reveals — not for every section.
3. **Mobile first.** One clear task/focus per screen; large touch targets; no hover dependency.
4. **Accessible by default.** Every business, agent, metric, and CTA must exist as semantic text/UI outside WebGL.
5. **Deterministic first.** Simulate agent behavior locally before considering live OpenAI Agents SDK.
6. **Tiny puzzles.** 5–20 seconds, optional, skip/autosolve available.
7. **Proof before spectacle.** Projects, field notes, CTA, and business outcomes must remain visible and clear.

## Phase 0 — Finalize product spec before code

### Step 0.1: Choose the first playable slice

**Objective:** Avoid overbuilding the whole simulator before proving the mechanic.

Recommended first slice:

```text
3 businesses running in parallel
+ 3 simulated agents
+ 1 business inspector
+ 1 Three.js constellation panel
+ 1 agent assignment interaction
+ metrics changing from Noisy → Coherent
```

Do **not** start with six businesses, all puzzles, live agents, or full IPO finale.

### Step 0.2: Define acceptance criteria

The first prototype is successful if:

- visitor immediately understands they are orchestrating businesses
- visitor can assign one agent to one business
- one business visibly improves
- portfolio-level metric changes
- CTA remains visible without solving anything
- mobile layout has no horizontal overflow
- page still makes sense if WebGL fails

### Step 0.3: Confirm route strategy

Recommended:

```text
app/v2/page.tsx
```

Keep current homepage unchanged until v2 proves itself.

## Phase 4 — Add the first selective Three.js scene

### Step 4.1: Business constellation scene

**Create:**

```text
components/v2/BusinessConstellationScene.tsx
```

Purpose:

- show businesses as constellation/cell nodes
- show active business highlighted
- show agent movement when assigned
- show improvement as visual stabilization

This scene should not contain critical text.

### Step 4.2: Reduced motion and fallback

Requirements:

- respect `prefers-reduced-motion`
- render a static frame or fallback visual
- do not block page if WebGL fails
- cleanup renderer/geometries/materials on unmount

### Step 4.3: Mobile visual budget

On mobile:

- one constellation area
- no dense particle effects
- no precision dragging required
- scene should load fast and not block content

Run:

```bash
npm run lint
npm run build
```

Then visually verify:

- desktop `/v2`
- mobile `390x844`
- reduced motion if possible

## Phase 5 — Add one tiny puzzle

### Step 5.1: Choose first puzzle

Recommended first puzzle:

```text
Assign Architecture Agent to AI Startup → connect three scattered signals into one product core
```

The puzzle can be tap-based, not drag-heavy.

### Step 5.2: Make puzzle optional

Controls:

- `Solve`
- `Auto-Orchestrate`
- `Skip`

The visitor should never need to solve the puzzle to see proof/contact.

### Step 5.3: Reward animation

When solved:

- constellation node stabilizes
- metric changes `Noisy → Coherent`
- event log says what Scott's intervention accomplished
- CTA becomes more context-aware, e.g. `Book an Architecture Review`

## Phase 8 — Optional OpenAI Agents SDK exploration

Do **not** add live agent calls until this phase.

Before implementation, decide:

- what visitor input is allowed
- whether any data is stored
- API cost limit
- rate limiting
- abuse prevention
- server runtime support
- fallback if API fails

Possible first live feature:

```text
Architecture Review Teaser
```

Visitor selects a business/problem from predefined options, and constrained agents return a short structured recommendation.

## Phase 9 — Validation and iteration

### Technical validation

Run every time:

```bash
npm run lint
npm run build
```

Browser checks:

- desktop visual check
- mobile visual check
- no JS console errors
- no horizontal overflow
- CTA accessible without puzzle completion
- WebGL fallback acceptable

### Product validation

Ask:

- Does the first screen clarify the hiring problem?
- Does the visitor understand they are orchestrating businesses?
- Does the simulator make Agentic Engineering more concrete?
- Is Three.js helping or distracting?
- Would a CTO/founder know what to do next?

### Success metric

North star:

```text
Qualified conversations with people who understand Scott as an Agentic Engineering / AI Systems Architecture partner.
```
