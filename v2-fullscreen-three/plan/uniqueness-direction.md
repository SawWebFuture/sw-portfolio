# v2 Uniqueness Direction

Scott's guidance: **the new portfolio should be really unique and different.**

This means v2 should avoid feeling like:

- a standard SaaS landing page
- a typical developer portfolio
- a scroll stack of cards
- a template with decorative WebGL
- a slightly improved version of the current site

## Creative north star

Build an interactive artifact that feels like entering Scott's operating system for Agentic Engineering.

A visitor should think:

> "I have not seen a portfolio like this before — this person thinks in systems."

## Proposed experience model

### 1. One continuous living scene

Instead of separate boxed sections, use one fullscreen Three.js world that transforms as the visitor moves through states:

- system cube / architecture core
- agent swarm / orchestration layer
- water flow / business fit
- flower-of-life / autonomy
- textured tree / quality and growth
- project constellations / proof
- contact portal / collaboration

HTML content can appear as calm overlays, but the 3D world should be the main continuity.

### 2. Navigation as a spatial instrument

Replace a typical nav bar with something more distinctive:

- constellation nodes
- compass / orbital menu
- minimal bottom rail on mobile
- section labels that feel like system states: `Signal`, `Swarm`, `Flow`, `Proof`, `Field Notes`, `Contact`

### 3. Nature + math + agentic technology

The visual identity should combine:

- trees and roots
- flowing water
- flower-of-life geometry
- constellations
- glass architecture blocks
- signal paths
- AI agent nodes
- equations / geometric linework

The goal is not sci-fi for sci-fi's sake. It should communicate systems that are alive, intelligent, private, and useful.

### 4. Mobile-first wonder

Mobile should not be a reduced desktop. It should feel intentionally designed:

- one large focal object per screen
- thumb-friendly state controls
- horizontal proof carousel
- short text bursts
- smooth but restrained motion
- reduced-motion fallback

### 5. Content should feel authored, not generic

Use language around:

- Agentic Engineering
- local-first AI
- autonomous agents
- edge/local LLM orchestration
- privacy-first workflows
- zero-downtime modernization
- product-driven systems architecture

Avoid generic language like:

- "I build apps"
- "scalable digital products"
- "beautiful user experiences"
- "full-stack developer portfolio"

## Differentiating ideas to consider

### Option A: Agentic Observatory

A dark/white hybrid observatory where every service/project is a star system. Agent swarms orbit and connect across systems. Visitor navigates through constellations.

Best for: sophisticated, systems architect, AI command-surface feel.

### Option B: Systems Garden

A clean white world where geometry grows into trees, water flows through business systems, and agent nodes pollinate architecture blocks.

Best for: nature + tech/math, calm but memorable, human-centered AI.

### Option C: Living Blueprint

A full-screen technical blueprint that constructs itself as the visitor scrolls. Legacy blocks reorganize into modern architecture, with AI agents acting as builders.

Best for: modernization credibility, consulting clarity, enterprise audience.

### Option D: Local-First Lab

A playful interactive lab where local models, agents, and tools are physical objects. Visitors tap systems to see capabilities.

Best for: technical uniqueness, showing hands-on AI workflow personality.

## Recommended blend

Use **Systems Garden + Agentic Observatory**:

- white / clean base for elegance
- teal/orange accents for continuity
- one persistent 3D world
- nature/math motifs for uniqueness
- observatory/state navigation for sophistication
- project proof as constellations

4. Should we use real CC0 models, procedural geometry, or a blend?
5. Should v2 eventually replace the current homepage or live at `/v2` first?
